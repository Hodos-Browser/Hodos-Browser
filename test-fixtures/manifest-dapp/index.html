Hodos Manifest Connect Test

This page exercises the manifest_connect_bundle prompt. It must be served over HTTPS from the same origin that hosts /.well-known/wallet-manifest.json, and the wallet call must go through the window.CWI shim (IPC transport) — that is the path Phase 2.6-G G.4 made Rust-authoritative. From an unknown (not-yet-approved) origin, the first shim call triggers the rich manifest bundle modal instead of the plain domain-approval modal. 

Ready. Click Connect.

The second button exists to answer UI_FOLLOWUPS.md §4: the connect modal displays a Level-2 counterparty but the grant row is written with counterparty = NULL. Before changing what gets written we have to know what the counterparty actually is at request time for a protocol the manifest declares as "self". This fires exactly that call — [2, 'server hmac'], which /manifest.json declares with counterparty: "self" — so the wallet log shows what dispatch_scoped_grant builds into ScopedCall::Protocol{ counterparty }. Run it with quiet mode OFF, or the grant is never consulted.
